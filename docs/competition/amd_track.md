# AMD 自主命题赛道项目定位

## 题目

**面向 ADAS 算法验证的 Zynq 软硬协同实时视觉平台——照片 HIL 与硬件安全岛**

## 一句话介绍

用真实数据集照片构造可复现的 ADAS 测试场景，在 Zynq 上完成
OV5640 → PL → VDMA → PS 感知/OSD → LCD 的实时闭环，并用 PL 决策 FSM
和独立看门狗验证“PS 失效时仍能安全停车/报警”的硬件安全机制。

## 解决什么问题

- 真实道路/车辆测试成本高、不可复现、受天气和场地限制；
- 纯 PC 仿真无法展示摄像头、LCD、硬件时序和失效安全；
- 只用视频回放的 demo 无法说明“实时链路”和“PS 卡死后的行为”。

照片 HIL 让同一张数据集图同时用于离线指标和现场拍摄，场景可重复；
PL 安全岛让决策执行不依赖 Linux/Jupyter 是否存活。

## AMD 平台为什么不可替代

| 角色 | 实现 |
|---|---|
| PL | 摄像头视频旁路、灰度/彩色选择、VDMA、决策 FSM、500 ms 看门狗、LED/蜂鸣器 |
| PS | OpenCV 红绿灯、车道线、静态障碍物、OSD 绘制 |
| VDMA | 摄像头帧与 LCD 帧的 DDR 双缓冲 |
| 安全岛 | PS 停心跳后 PL 独立进入安全态，不依赖 Linux 调度 |

相比树莓派/PC，Zynq 的价值不是“通用算力更大”，而是**视频通路确定、
PL 灰度预处理、硬件失效安全和软硬分工清楚**。车道模式已经真实使用
PL RGB→灰度结果，PS 侧跳过重复颜色转换。

## 当前可验证结果

- 45/45 自动测试；
- PL 直通 37.8 FPS；
- 三模式实测：红绿灯 23.0 FPS、车道线 20.5 FPS（PL 灰度）、障碍物 26.8 FPS；
- 车道输入 A/B：彩色输入 19.54 FPS，PL 灰度输入 20.52 FPS，提升 5.02%；
- 红/绿/黄控制条件各 20/20；
- BSTLD 圆形灯留出识别 31/40；无灯负样本 10/10；
- TuSimple 左右侧 SOLID/DASHED 留出识别 16/20；
- 实线/虚线现场稳定性各 12/12；
- 小环境静态障碍物 `OBJECT NEAR` + `alarm_reason=3`；
- OSD 处理卡死 1.5 s 后 `wd_timeout=1`，恢复后自动清零。

## 创新点

1. **照片 HIL 测试方法**：打印/手机显示真实数据集图，现场与离线共用样本；
2. **硬件安全岛**：PS 卡死时 PL 独立执行安全决策和报警；
3. **双模式视频**：零 CPU VDMA tie 直通 vs PS OSD 回写，可直接对比；
4. **真实问题闭环**：定位并修复 PYNQ GPIO 写掩码、层次驱动匹配、OV5640 闪光灯寄存器；
5. **小环境静态障碍物**：空场景学背景，支持静态物体框选和近区报警。
6. **PL 灰度预处理加速**：车道模式免去 PS 重复 RGB→灰度和灰度伪图 HSV 转换。

## 已知边界

- BSTLD 本地镜像是部分数据，黄色仅 1 个真实源框；算法只支持圆形灯，
  箭头灯因圆度不足会被主动拒绝；
- TuSimple 官方无实/虚标签，20 帧由人工标注；单帧侧标签留出准确率为 80%；
- 320×240 感知是实时性折中，当前高分辨率 OSD 不作为实时主模式；
- 小环境障碍物模式要求固定相机和空场景背景；
- 不是车规产品，定位是教学、算法验证和原型平台。

## 现场演示顺序

直通 → 红/绿/黄 → 车道实线/虚线 → 看门狗 → 小环境障碍物 → 图片注入兜底。
所有失败场景都准备离线图片注入作为兜底。
